# v1 boundaries

- Independent reviewer identity is a claimed string, not an authenticated attestation. Protected CI administration is required.
- The runner is not a sandbox; trusted policy commands have the local OS account's file/network access.
- Ignored files and dependencies are not part of source hashing. Pin dependencies and protect the environment. Pre-existing ignored application inputs used by configured commands are not run-bound; later changes to those inputs do not invalidate evidence. Do not rely on ignored application files as gate inputs. CI starts from a fresh candidate snapshot, but candidate code and any files it creates remain untrusted.
- Git submodules, symlinked source and Windows execution are unsupported in v1.
- Concurrent hostile filesystem mutations by a local writer cannot be comprehensively prevented by a userspace CLI; hashes and locks defend normal stale/concurrent operation.
- Default initialization intentionally has empty required commands and project-document TODOs. It must reject completion until configured.
- **CI is a mechanical execution gate, not semantic verification.** The repository's `pull_request` workflow definition comes from the PR merge commit, as described in GitHub's [Actions security guidance](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target), so Actions alone is not a trust anchor. Protected `main` requires strict `gate` from GitHub Actions App `15368` and `buildkite/aicg-trusted-gate/pr` from Buildkite App `805657`; the Buildkite App is limited to this repository. The rule requires PRs and up-to-date checks, applies to admins, requires conversation resolution, and blocks force-push/deletion; human approvals remain zero by repository choice. [Buildkite Build #12](https://buildkite.com/himitsuomom/aicg-trusted-gate/builds/12) passed on PR #10's head and [Build #13](https://buildkite.com/himitsuomom/aicg-trusted-gate/builds/13) passed on merged `main` at `0069865`. The required Buildkite status prevents bypass by changing only the PR's Actions workflow. However, the trusted pipeline still executes PR-controlled application and test code without network access or secrets, so that code can falsify its own mechanical evidence. This repository sets `independent_verification_required: false`; a green Buildkite check does not authenticate a semantic reviewer or prove code benign. The independent review memo remains `INSUFFICIENT_EVIDENCE` and is not imported as verifier evidence.
- **Run evidence has two storage paths.** Local `.ai/evidence/` and `.ai/runs/` files are gitignored and do not travel with a clone. GitHub Actions uploads a run artifact; use the linked Actions run for published evidence.
