# v1 boundaries

- Independent reviewer identity is a claimed string, not an authenticated attestation. Protected CI administration is required.
- The runner is not a sandbox; trusted policy commands have the local OS account's file/network access.
- Ignored files and dependencies are not part of source hashing. Pin dependencies and protect the environment.
- Git submodules, symlinked source and Windows execution are unsupported in v1.
- Concurrent hostile filesystem mutations by a local writer cannot be comprehensively prevented by a userspace CLI; hashes and locks defend normal stale/concurrent operation.
- Default initialization intentionally has empty required commands and project-document TODOs. It must reject completion until configured.
- **PR workflow is not an independent trust anchor.** The repository's `pull_request` workflow definition is loaded from the pull request merge commit, as described in GitHub's [Actions security guidance](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target). The public `main` branch requires only the `gate` status from GitHub Actions and does not require PR approval. A pull request can change its workflow to report `gate` success without running the governance checks. Branch protection still blocks missing or failed checks, but it does not defend against a hostile change to the workflow itself. A separate public [Buildkite trusted-CI configuration](https://github.com/himitsuomom/aicg-trusted-ci) is prepared, but the Buildkite GitHub App is not connected and its check is not required by branch protection. Until a real Buildkite PR run succeeds and the exact App-sourced status is required on `main`, treat the current GitHub Actions check as protection against accidental regressions only, not adversarial PRs. Even once active, that mechanical gate will run PR-controlled application and test code without secrets or network access; it is not an authenticated semantic review and cannot prove the code benign.
- **Run evidence has two storage paths.** Local `.ai/evidence/` and `.ai/runs/` files are gitignored and do not travel with a clone. GitHub Actions uploads a run artifact; use the linked Actions run for published evidence.
